# 本机执行流程

1. 确定权限和范围。记录目标的备注/昵称/微信号中已知字段，必要时明确微信账号；未指定范围时按用户意图确认全会话或起止时间。禁止把多项候选取第一项。
2. 检查 Windows 架构、磁盘空间、Apple 软件、USB 识别及自动化能力。只读取识别所需元数据。若已有备份，检查 Info.plist 时间、Manifest.plist 加密、Status.plist 完成状态和 Manifest.db 结构。
3. 用户要求当前手机记录而备份过期时，使用 Apple 官方本地备份流程。需要用户解锁、信任、输入密码时给出单步提示。不要关闭防护、重置备份密码或擅自覆盖重要旧备份。此项目不直接操作苹果 GUI，也不承诺 Apple Devices 所有版本兼容。
4. 在源码/Git/云同步目录外建立全新 case_dir，写外部配置。`time_range` 的起止都用含时区的整秒 ISO 8601；不明确时询问。一天的结束值是次日零点，不是当天 23:59:59。
5. 运行 identify，只输出数量。本地身份文件出现多个账号、同名联系人或字段不一致就停止；让用户核对必要元数据，调整配置后使用新目录。不要展示其他会话内容。
6. 运行 inventory、prepare。前者检查单一目标表/分片及记录数；后者按窗口提取，不改原始备份。缺失字典留下逐条说明；只有可靠取得的匹配字典才能配置，不能把字典 ID 当作密钥。
7. 默认直接进入 media。用户需要转换且有离线环境时，用 tools/fetch_upstream.py 安装固定版本，校验后配置 upstream 并运行 official。`--format` 不能保证上游 CLI 产生 TXT，本项目自己生成 UTF-8 TXT。
8. 运行 media、render、verify。verify 失败就保留原物、记录摘要并排查；不能把“程序退出 0”视为完整性证据。空范围应产出 0 条的有效文件。
9. 在用户本机打开成果核对，必要时由用户对照手机抽样。结果包含明确的未解析/未找到提示时，必须在交付报告说明。没有 phone UI 证据就写未验证。
10. 用户另行授权清理时先清单化：成果、资源、原备份、工作副本、工具各自路径与大小，核对全部引用后才按白名单操作。本项目本身无删除接口。

## 故障区分

- Manifest.db 缺失或未完成：处理备份完成状态，不伪造元数据。
- Manifest.plist 表示加密或数据库非 SQLite：明确不支持，不声称已解密。
- 多消息分片/未知表结构：停止；目前没有自动合并能力。
- Zstd 字典缺失：保留原字节和占位；不能删掉记录。
- TXT 乱码：先区分源未解压、源本身替换字符、编码问题，不通过删字掩盖。
- 媒体缺失：记录 source missing、范围无法归属、格式不能验证或未启用转换。文件数量不等于附件消息数量。
- 防护拦截：记录具体错误，告知用户；不换路径或关闭防护来绕过。

## 最少交付信息

HTML/TXT 的绝对路径、备份时间（实际可读时）、目标与筛选窗口、时区、源/导出记录数、可读及未解析数、媒体核验统计、未验证检查、临时数据位置及加密设置变化。用户身份仅在本地报告记录，不上传。
